# Switch

> **小猫声明：禁二传二改以及商业盈利，引流注明出处**

聊天界面的壁纸与配色切换。一颗按钮换背景，整套主题颜色跟着翻。

两套实现，各自独立，拿哪套都行：

| 目录 | 是什么 | 规模 |
|---|---|---|
| [`web/`](web/) | 纯 CSS + 原生 JS。一颗按钮在几张壁纸间随机轮换，主题变量整套跟着翻。 | ~150 行 |
| [`ios/`](ios/) | SwiftUI。完整的壁纸 + 配色系统：九宫格选壁纸、从相册加、色相/明暗双滑杆调三处颜色、全局字色、气泡透明度、背景模糊度。 | ~1200 行 |

两边解决的是同一个问题，深度不同：web 版是"换张背景图"，iOS 版是"让用户把整个界面调成自己喜欢的样子"。

## 先看效果

**Web**：直接双击 `web/demo.html`，不用起服务器。壁纸是 CSS 渐变占位，五张里有两张深色，切过去能看到整套主题翻转。

**iOS**：`ios/` 是个 Swift Package，加进你的项目后：

```swift
NavigationStack {
    WallpaperView().navigationTitle("聊天壁纸")
}
```

## ⚠️ 仓库里没有壁纸图

一张图片都没有，`assets/` 是空的。壁纸素材版权情况各不相同，不适合跟代码一起分发。

- **web**：把图放 `assets/`，改 `web/switch.js` 和 `web/switch-boot.js` 里的 `WALLS`（两处都要改，原因见 web/README）
- **iOS**：把图拖进 `Assets.xcassets`，把名字写进 `Theme.walls`

不放图也能跑：web 版 demo 用的是 CSS 渐变；iOS 版 `Theme.walls` 留空时设置页只显示一个"＋"（从相册加），不会崩。

请只使用你自己拥有或已获授权的素材。

## 几条从踩坑里长出来的规矩

这套东西真正的价值不在代码量，在下面这些 —— 每一条都是撞过才写进去的：

**壁纸必须铺在独立的固定层上**，不是 `body` 的 background。body 背景跟着文档滚，长列表滚到底图就跑没了。

**防首屏闪烁的脚本必须内联在 `<head>`**，不能改成外链。外链要等一次网络往返，在它回来之前首屏已经按默认色渲染过一帧 —— 用户看到的就是开屏白闪一下。

**底色永远站在字色的对面。** 字白就深底，字黑就浅底。没被单独调过的地方也要跟着字色翻，否则用户选了白字之后，出厂的白气泡就是一屏看不见的字 —— 那不是"用户选的样子"，是个坏状态。

**底色不跟主题翻的控件，字色要单独开一档。** iOS 和 web 两边都在输入框上栽过：输入框在深色主题下仍是浅底，图省事给里面的字复用了"次要文字色"（浅色），结果是白底上一行浅灰字，基本看不见 —— 而那恰恰是最需要看清的一行。

**调色的第二根滑杆是完整明暗轴，不是饱和度。** `0 = 白 / 0.5 = 纯色 / 1 = 黑`，后半段一路掉饱和所以经过灰。只做"白→纯色"的话，用户滑到头也调不出灰和黑。

**纯白和纯黑那两头没有色相可言。** 停在那儿拖色相条屏幕上什么都不会变，用户会以为控件坏了。所以从两头第一次拖色相时，顺手往中间挪一点点。

**用户自己加的图不能放 Caches。** 系统缺空间时会直接删掉，没有任何提示，表现成"壁纸自己变回默认的了"。要放 Application Support。

更多细节在两个子目录各自的 README 和代码注释里。
